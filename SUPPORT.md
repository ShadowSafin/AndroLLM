# Support

Thank you for using AndroLLM. This document outlines how to get help and support.

---

## Getting Help

### 1. Documentation

Start with the documentation — most common questions are answered there:

- **[README.md](README.md)** — Quick overview and quick start
- **[FAQ.md](documentation/FAQ.md)** — Frequently asked questions
- **[TROUBLESHOOTING.md](documentation/TROUBLESHOOTING.md)** — Common issues and solutions
- **`documentation/` directory** — Deep technical documentation

### 2. Issue Tracker

Search [existing issues](https://github.com/your-org/androllm/issues) before opening a new one.
Many problems have already been reported and resolved.

**Bug Reports:**
- Use the bug report template
- Include device model, Android version, and app version
- Attach logs from Settings → Logs & Diagnostics
- Describe steps to reproduce clearly

**Feature Requests:**
- Use the feature request template
- Explain the problem you're trying to solve
- Suggest a solution if you have one

### 3. Security Vulnerabilities

See [SECURITY.md](SECURITY.md) for responsible disclosure procedures.
**Do not file security issues in the public issue tracker.**

## What to Include When Asking for Help

To get the fastest resolution, please include:

1. **Device info**: Model name, Android version, RAM
2. **App version**: From Settings → About
3. **Steps to reproduce**: Exact actions that trigger the issue
4. **Expected vs. actual behavior**: What you expected vs. what happened
5. **Logs**: Export from Settings → Logs & Diagnostics
6. **Screenshots**: If the issue is visual

---

## Limitations

- Response time is best-effort; this is a community-driven project
- We cannot guarantee fixes for issues specific to rare device configurations
- Cloud provider outages are outside our control — check the provider's status page
- Voice assistant limitations may stem from Android background execution restrictions on your device manufacturer
